How OpenLid Works

Why standard tools fail when the lid closes, and how OpenLid manages power safely.

01

The Clamshell Interrupt

macOS does not treat closing the laptop lid as an idle event. It triggers a hardware interrupt in IOPMrootDomain that bypasses normal user-space assertions like caffeinate or NSProcessInfo.beginActivity.

02

Kernel Assertion Toggle

OpenLid modulates the kernel's sleep-disabled flag via pmset -a disablesleep 1 alongside an active kIOPMAssertionTypePreventSystemSleep handle, keeping CPU, networking, and disks operating without keeping the screen illuminated.

03

Zero-Prompt Touch ID Helper

Elevated power management normally requires a sudo password. OpenLid installs a minimal, scoped sudoers file (/etc/sudoers.d/openlid) via Touch ID once, permitting subsequent state changes in under 40 milliseconds without popups.

Hardware Safety by Design

Running closed-lid workflows without an external monitor can trap heat if airflow is obstructed. OpenLid incorporates two automatic safety breakers to prevent hardware damage:

🌡️
Thermal Overheating Breaker:

Polls ProcessInfo.processInfo.thermalState continuously. If thermal pressure reaches .serious or .critical, OpenLid immediately drops assertions and permits the Mac to sleep safely.

🔋
Battery Floor Threshold:

Configurable cutoff (default 15%). When running on battery power, sleep prevention automatically halts if the battery drops below your safety margin.

🛡️
Signal Trap Cleanup:

Traps SIGINT, SIGTERM, and app crashes to guarantee power settings are restored to default state upon termination.
